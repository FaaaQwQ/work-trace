# Work trace · 工作留痕

<p align="center"><img src="aw-qt/media/worktrace.svg" width="72" alt="Work trace 藏羚图标"></p>

Work trace 是一个以 Windows 桌面为主要使用环境的本地工作记录工具，基于 ActivityWatch 改造。它在后台记录电脑活动，通过顶部悬浮栏补充工作事项，并将活动与人工记录整理为每日、每周、每月和项目总结。

适合个人工作复盘、阶段汇报、项目过程记录，以及整理会议、线下工作等电脑活动无法直接反映的信息。

> 当前为源码运行版本。总结由本地规则和模板生成，尚未接入大语言模型；应用使用时长反映时间投入，不能自动判断工作成果。

## 功能概览

| 功能 | 当前实现 |
| --- | --- |
| 后台活动记录 | 记录前台应用、窗口标题和持续时间，结合离开电脑状态计算活跃时间 |
| 顶部悬浮栏 | 置顶显示，平时收为细条；鼠标移入展开，移出自动收起 |
| 快速记录 | 记一笔、完成事项、里程碑，可选择项目、发生时间和补录时长 |
| 项目管理 | 新建、编辑、切换当前项目、归档与恢复 |
| 工作台 | 按日期和项目查看工作记录、活跃时间、补录时间、应用活动明细 |
| 日 / 周 / 月总结 | 手动生成，也可自动补齐已结束周期的总结 |
| 项目总结 | 按指定项目与日期范围汇总，适用于重大项目和阶段复盘 |
| 人工补充 | 编辑、删除记录，修改总结内容并导出 Markdown |
| 暂停与继续 | 悬浮栏或工作台控制采集暂停，恢复后重新计算记录区间 |
| 登录自启动 | Windows 首次启动尝试启用，之后可在托盘菜单中关闭 |
| 本地存储 | 默认保存到桌面「Work trace记录」，不需要配置云数据库 |
| 系统风格 | Windows 设置式布局、藏羚透明图标、浅色与深色适配 |

## 使用方式

### 1. 后台记录

启动后会运行本地服务、窗口采集器、离开状态采集器和托盘程序。工作台默认地址为：

**http://127.0.0.1:5610/#/worktrace**

窗口采集器记录应用名称和窗口标题；离开状态用于排除离开电脑的时间。暂停记录时，采集器停止写入新的活动心跳；历史记录继续保留。

当前启用的采集器不保存按键内容、截图、录音或文档正文。窗口标题可能包含文件名称等信息，仍应按个人工作数据管理。工作留痕功能在本机运行，安装依赖和使用上游界面中的外部链接可能需要联网。

### 2. 顶部悬浮栏

- 启动时短暂展开，随后收为屏幕顶部的一条细线。
- 鼠标移到顶部细线处展开，移开后自动收起。
- 打开下拉菜单或记录弹窗时保持展开。
- 点击藏羚图标打开工作台；拖动「Work trace」文字调整顶部位置。
- 当前项目下拉框可切换项目或新建项目。
- 「记一笔」用于工作记录，「完成」用于完成事项，「暂停 / 继续」控制采集。
- 「总结」菜单可生成日、周、月总结，并记录里程碑。
- 看不到悬浮栏时，打开 Windows 右下角托盘菜单，选择「显示顶部悬浮栏」。

### 3. 工作记录与人工补充

支持五种记录：**工作记录、完成事项、里程碑、问题、下一步**。

每条记录可以关联项目、设置发生时间、填写补录时长。默认只显示主要字段，时间和时长在「更多选项」中展开。可通过每条记录右侧的更多菜单编辑或删除。

人工补录适用于会议、电话沟通、外出、纸面工作等场景。补录时长与电脑活跃时间分开显示，避免直接相加造成重复统计。

### 4. 项目管理

创建项目后，选择「开始记录」或在悬浮栏切换当前项目。自动活动根据当时选中的项目归属，人工记录也可单独选择项目。

项目支持说明、编辑、归档和恢复。归档后从常用项目列表隐藏，原有记录保留。「显示已归档」可查看并恢复。项目归属依赖手动切换，当前不会根据窗口标题自动识别项目。

### 5. 总结中心

| 类型 | 范围 |
| --- | --- |
| 每日总结 | 所选日期 |
| 每周总结 | 所选日期所在周，周一至周日 |
| 每月总结 | 所选日期所在自然月 |
| 项目总结 | 指定项目及开始、结束日期 |

总结包含电脑活跃时间、人工补录时间、应用投入，以及五类人工记录。默认以阅读模式展示，点击「编辑」后可以修改 Markdown 内容，保存时同步更新导出文件。

再次生成同一类型、周期和项目的总结会打开已有结果，保留人工修改；「重新生成」会明确提示覆盖现有内容。

在设置中开启自动总结后，程序每隔约 30 秒检查已结束日期，补齐日总结，并在对应周末、月末补齐周报和月报。关闭程序期间不会后台生成，重新运行后再补齐。当天、当周或当月尚未结束时可手动生成；手动生成的旧结果不会被自动覆盖，更新活动后可按需重新生成。

### 6. 设置与存储

工作台设置提供自动总结开关、保存位置与路径复制；托盘提供工作台、悬浮栏、记录文件夹、登录自启动和退出入口。

默认目录位于当前 Windows 用户的实际桌面：

```text
桌面/Work trace记录/
├── data/           # 工作留痕数据库与 ActivityWatch 活动数据库
├── config/         # 服务、采集器和悬浮栏设置
├── logs/           # 各模块运行日志
├── cache/          # 运行时缓存（按需生成）
└── 总结/           # 导出的 Markdown 总结
```

源码目录下的 `logs/startup.log` 另行保存启动输出与原生异常信息。

请通过工作台修改总结；直接编辑导出的 `.md` 不会自动写回数据库。备份时先从托盘退出，再复制整个「Work trace记录」目录，不要只复制导出的总结。

## 从源码安装（Windows）

### 环境

- Python **3.12**：当前版本已在 3.12 验证；窗口采集依赖固定为 pywin32 306，不建议直接使用 Python 3.13。
- Node.js 与 npm：本地构建使用 **Node.js 24** 验证。
- 安装依赖时需要联网；安装完成后，工作留痕核心功能使用本地服务。

源码上传包不包含 `.venv`、`node_modules` 或预编译界面，下载后需完成以下步骤。不能把其他电脑的虚拟环境直接复制过来使用。

### 安装 Python 依赖

在项目根目录打开 PowerShell：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements-worktrace.txt
```

依赖文件会以可编辑方式安装本项目六个 Python 模块，同时安装 PyQt6。业务模块必须使用这里的本地源码，不能只安装 PyPI 原版 ActivityWatch 包代替。

### 构建工作台

```powershell
cd aw-server\aw-webui
npm.cmd ci
npm.cmd run build -- --dest ../aw_server/static
cd ..\..
```

界面输出到 `aw-server/aw_server/static`，由本地 Python 服务提供。后续修改 Vue 界面时需要重新构建并刷新浏览器。

### 启动

双击根目录的 **`启动 Work trace.cmd`**。也可在 PowerShell 中启动，直接查看错误：

```powershell
.\.venv\Scripts\python.exe .\worktrace.py
```

Python 源码修改后，从托盘退出应用再重新启动。

### 可选启动参数

```powershell
# 指定记录目录
.\.venv\Scripts\python.exe .\worktrace.py --data-dir "D:\WorkTraceData"

# 本次启动不尝试注册开机自启动；不移除已经存在的自启动配置
.\.venv\Scripts\python.exe .\worktrace.py --no-autostart

# 隔离测试实例：使用 5666 端口、指定目录下的 profiles/testing
.\.venv\Scripts\python.exe .\worktrace.py --testing --data-dir ".\local-test-data"
```

更换源码位置或记录目录后，请检查托盘中的自启动配置是否仍指向当前路径。

## 项目结构

GitHub 源码包已将运行所需子模块展开为普通目录，不依赖嵌套 Git 仓库：

```text
Work trace/
├── README.md
├── LICENSE.txt
├── requirements-worktrace.txt
├── worktrace.py                       # 数据目录、端口与启动入口
├── 启动 Work trace.cmd
├── aw-core/                           # 共享模型、存储、采集暂停状态
├── aw-client/                         # 采集器与服务的通信客户端
├── aw-server/
│   ├── aw_server/worktrace.py          # 项目、记录、总结、自动调度与接口
│   └── aw-webui/
│       └── src/views/WorkTrace.vue     # 工作台界面
├── aw-qt/
│   ├── aw_qt/worktrace.py              # 顶部悬浮栏与快捷记录
│   └── media/worktrace.*               # 藏羚图标
├── aw-watcher-window/                 # 前台窗口采集
├── aw-watcher-afk/                    # 离开电脑状态采集
└── scripts/tests/                     # Work trace 业务与桌面回归测试
```

技术组成：Python、Flask、SQLite、PyQt6、Vue 2，以及 ActivityWatch 的采集与事件存储模块。界面采用现有项目技术栈，没有引入新的前端框架。

工作留痕 API 前缀为 `/api/0/worktrace`，包括 `/state`、`/projects`、`/notes`、`/overview`、`/reports`。服务默认仅监听本机 `127.0.0.1`；当前没有面向公网的账号、权限和多租户机制。

## 常见问题

**双击没有界面？**

先查看托盘是否已有实例。悬浮栏默认会自动收起，可从托盘选择「显示顶部悬浮栏」。若没有运行，使用上面的控制台启动命令查看错误，或检查源码目录的 `logs/startup.log`。

**提示缺少 Python 环境或模块？**

在当前源码根目录重新创建 `.venv` 并安装 `requirements-worktrace.txt`。本机快捷方式 `.lnk` 含机器路径，因此没有放进 GitHub 源码包。

**工作台打不开、空白或界面没有更新？**

确认完成前端构建、服务已运行，并访问 5610 端口的地址。修改前端后重新构建并刷新；默认 ActivityWatch 的 5600 端口不是本项目的工作台地址。

**活跃时间为零？**

检查是否暂停记录、采集器是否正常启动，以及所选日期和项目是否正确。仅使用本地服务而没有运行采集器时，也可以人工记事，但不会产生新的电脑活跃时间。

**总结没有自动更新？**

自动任务处理已结束周期，并保留已有总结中的人工修改。需要更新已经存在的总结时，使用「重新生成」；覆盖前请确认人工修改是否需要保留。
